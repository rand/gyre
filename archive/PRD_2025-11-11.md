# PRD — Gyre — Proactive Agentic Memory Supervisor (Gyre)

> **Status:** Archived on 2025-02-XX. Superseded by `PRD.md` but retained for traceability.

Date: 2025-11-11
Owner: You
Status: Draft-ready

## Problem
Teams run multiple LLM agents (Claude Code, Codex, Gemini, etc.). Context is scattered across chats, tools, files, and prior episodes. Agents forget, request redundant info, and hallucinate. Human supervisors manually paste context. This wastes tokens, time, and attention.

## Vision
Gyre observes sessions passively and injects precisely the smallest useful, policy-safe **context patches** at the right moments. It unifies memory, on-demand retrieval, and tool results into a single selection surface that maximizes **efficacy per token** under strict budgets.

## Users
- Primary: AI agents (via API) and engineers operating them.
- Secondary: PMs, SREs, compliance officers auditing provenance and policy.
- Tertiary: End users benefiting from higher quality, lower-latency agent output.

## Goals
- Lift task success while **reducing** injected tokens.
- Proactively assist without agent prompts; also answer explicit requests.
- Enforce zero policy violations and strong provenance.
- Be resilient, fast, and resource-frugal.

## Non‑goals
- Replacing the host agents’ reasoning loop.
- Full-text data lake search product; Gyre retrieves opportunistically.

## Key Requirements
1) **Observe**: Tap read-only streams from agent sessions, tools, IDEs. No dependence on agents writing into Gyre.
2) **Inject**: Deliver typed, minimal **Context Patch Protocol (CPP)** units into live sessions using provider transports (OpenAI Realtime, Anthropic Computer Use, Gemini function calling).
3) **Unify**: Treat memory items, live tool results, file chunks, skills, and deferred queries as uniform **Context Candidates** with the same scoring fields.
4) **Select**: Budgeted submodular selection (knapsack + MMR) over candidates with risk and latency caps.
5) **Compose**: Slot-based context blueprints with compression and citations.
6) **Learn**: Use DSPy signatures + optimizers (COPRO/MIPROv2) to auto-tune rank/summarize/redact/EV steps from logs.
7) **Govern**: Scope-aware redaction and audit. Bitemporal validity on facts.
8) **Resilience**: Backpressure queues, circuit breakers, degraded modes.
9) **Performance**: Target p95 observe→inject ≤ 600 ms; maintain token headroom for model reasoning; cache fragments.

## Metrics (SLOs & KPIs)
- Efficacy per 1k tokens (Δ success / 1k injected tokens) ↑
- Patch acceptance rate ↑; Redundancy ratio ↓; Staleness rate ↓
- Latency SLA: p95 ≤ 600 ms, p99 ≤ 1200 ms observe→inject
- Safety: 0 policy violations per 10k injections; 100% provenance coverage
- System: error budget < 0.1%; cost per successful assist ↓

## Release Plan
- M1: Passive observe + manual inject; DSPy COPRO on summarize/rank.
- M2: Proactive inject via CPP for one provider; EV-gated queries; redaction.
- M3: Temporal graph store + neighborhood retrieval; nightly consolidation.
- M4: Multi-agent skills library; cohort sharing with consent and scopes.

## Risks & Mitigations
- Over-injection → strict budgets, cool-downs, A/B throttles.
- Latency spikes → EV gate live queries; cache; circuit breakers.
- Privacy leakage → pre-compose redaction; scoped transports; audits.
- Graph cost → neighborhood-only; slow cadence global summaries.
